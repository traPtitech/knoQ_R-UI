# Merge-Readiness Pack の書き方

テンプレートは [merge-rationale.template.md](../_templates/merge-rationale.template.md) です．共通運用は [Missions README](../README.md) を参照してください．

`merge-rationale.md`は，レビュアーがマージ可否を判断し，必要な差分だけを詳しく確認するための終了資料です．受け入れ条件と検証結果を対応付けますが，作成者がマージを自己承認する文書ではありません．

## 作成手順

1. 対象 commit を固定し，Brief の version，計画承認，プロパティ承認，テスト設計承認を確認します．
2. 行ったこと，行わなかったこと，線引きの理由を Brief に沿って要約します．
3. Brief のプロパティ ID をそのまま Property Coverage 表へ移します．
4. 各プロパティに，実行した検証，出力へ結び付く証拠，`pass` / `fail` / `n-a` を対応させます．
5. 変更の影響範囲，重要な差分，残るリスクを示します．
6. CRPack，計画からの逸脱，外部操作の承認と結果を記録します．
7. レビュアーが判断欄へ直接コメントできる状態で提出します．

## 証拠の要件

証拠は次の 4 条件を満たします．

- **出力に結び付く**: 「修正した」という主張ではなく，対応するテスト，画面結果，静的解析，差分を示します．
- **機械で再確認できる**: 可能な限りコマンドと終了結果を残します．主観的な画面確認は対象状態と確認結果を記録します．
- **段階的に読める**: Pack には結論を置き，長いログやスクリーンショットはポインタで示します．
- **出所を追跡できる**: commit SHA，コマンド，日時，Node / npm などの環境，成果物の生成元を記録します．

knoQ_R-UI の標準候補は `npm run lint`，`npm run type-check`，`npm run build`，`npm exec -- vitest run --coverage.enabled=true` です．すべてを機械的に実行するのではなく，Brief のプロパティと変更範囲に合わせます．未実行項目は `not-run` と理由を記録します．証拠取得後に変更した場合は，対象 commit で再実行します．

## Property Coverage

Brief と同じ ID を使い，プロパティ，検証，証拠の対応を崩しません．`fail` や `n-a` を隠さず，未解決事項とマージ判断への影響を説明します．証拠のない `pass` は認めません．

## 判断記録

探索は採用した結論と理由だけを要約し，必要なら記録先を指します．Brief から逸脱した場合は CRPack の承認と Brief の更新先を示します．Issue，push，PR，デプロイなど外部操作を行った場合は，対象，明示的な承認，結果を記録します．

マージできない場合は `non_merge_root_cause` を `property-gap`，`evidence-missing`，`tool-gap`，`scope-drift`，`other` から選び，次の Brief 改善につながる形で理由を残します．

途中で担当を替える場合は [Handoff のガイド](./how-to-handoff.md) に未解決状態を戻します．

## 避けること

- 変更ファイルの列挙だけで，目的や証拠を示さないこと
- 異なる commit や実行環境の結果を出所なしで流用すること
- 長いログを Pack 本文に貼り，結論を埋もれさせること
- `fail`，未実行，未承認の外部操作を省略すること
