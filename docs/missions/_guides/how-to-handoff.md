# Handoff / Continuity Pack の書き方

テンプレートは [handoff.template.md](../_templates/handoff.template.md) です．共通運用は [Missions README](../README.md) を参照してください．

Handoff は，全履歴ではなく，次の担当が追加質問を最小限にして再開できる **最小再開状態** です．Brief が契約の正本であり，Handoff はその時点の実行状態を補います．

## いつ更新するか

- セッションまたは担当を切り替えるとき
- 承認待ちや外部要因で作業を止めるとき
- 長い作業の自然な区切りで，現在の状態が大きく変わったとき

## 残す内容

1. 完了，進行中，次の一手を，作業ツリーの状態も含めて記録します．
2. 現在も有効な決定と理由を残し，Brief へ反映済みか示します．
3. 再開に必要なソースだけを，強度，必要な理由，出所，最終確認日とともに指します．
4. blocker，承認待ち CRPack，未回答の問いを分けます．
5. 検証済みの commit，コマンド，結果と，まだ検証していない範囲を示します．
6. 探索を分離した場合は，生ログではなく場所，結論，採否を指します．

「次の一手」は「実装を続ける」ではなく，読むファイル，実行するコマンド，確認する判断など，再開直後の操作にします．

## 圧縮のルール

チャットや試行ログを丸ごと移しません．採用した結論と理由だけを残します．ただし圧縮時も，`must` / `should` の強度，元ソース，承認状態，対象 commit を失わないようにします．情報が古い場合は追記で補わず，現在有効な最小状態へ整理します．

## 再開する側

最初に [mission-brief.md のガイド](./how-to-mission-brief.md) に基づく Brief を読み，次に Handoff を読みます．Brief と矛盾する場合は勝手に選ばず，Brief を正として差分を CRPack で上申します．指定されていないコンテキストは，具体的に必要になるまで追加しません．

完了に近い場合は [Merge-Readiness Pack のガイド](./how-to-merge-rationale.md) に従い，Handoff の検証状態を証拠へ引き継ぎます．

## 避けること

- チャット全文や試行錯誤の生ログを貼ること
- 「現状を確認する」のように次の一手を曖昧にすること
- Brief と同じ契約情報を別内容で二重管理すること
- commit や承認状態を示さず，検証結果だけを引き継ぐこと
